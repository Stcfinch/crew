#### 操作敘述記錄

### 修改 3：步驟 7 — verify.md 新增隱藏區塊

在 verify.md 的每條驗證結果中，新增 HTML 註解區塊儲存操作敘述。此區塊**不影響**人類閱讀 verify.md，也**不影響** `--recheck` 解析邏輯（recheck 只解析 `❌ FAIL` 標記）。

**在每條驗證結果的末尾新增**：

```markdown
### [1] ✅ 可依日期範圍查詢
- **類型**：API
- **驗證**：`GET /api/xxx?startDate=...&endDate=...` → HTTP 200, 15 筆
- **截圖**：screenshots/verify-1-query-result.png
<!-- human_steps
- 操作：在查詢頁面的「開始日期」欄位輸入 2026-01-01，「結束日期」欄位輸入 2026-03-18
- 操作：點擊「查詢」按鈕
- 預期：系統顯示查詢結果，資料筆數大於 0
- 實際：系統回傳 15 筆資料，格式正確
-->
```

**設計理由**：
- HTML 註解在 Markdown 渲染時不可見 → verify.md 閱讀體驗不變
- `--recheck` 解析 `❌ FAIL` 時不會被註解干擾
- Word 報告產出時可解析此區塊取得人話敘述

### 4. 驗收摘要

| 欄位 | 資料來源 | 可自動填入 |
|------|---------|:---------:|
| 統計表 | `verify.md` 統計區塊 | ✅ |
| 一句話結論 | AI 依統計結果生成 | ✅ |

**Markdown 格式**：

```markdown
## 驗收摘要

| 狀態 | 數量 |
|------|------|
| 通過 | {N} |
| 未通過 | {N} |
| 略過 | {N} |
| 待人工確認 | {N} |

**結論**：{一句話摘要，如「共 6 項驗收條件，5 項通過、1 項待人工確認，整體驗收結果為通過。」}
```

**結論生成規則**：
- 全部 PASS → 「共 N 項驗收條件全數通過，建議進入正式上線流程。」
- 有 FAIL → 「共 N 項驗收條件，M 項未通過，需修正後重新驗證。」
- 有 MANUAL 無 FAIL → 「共 N 項驗收條件，M 項通過、K 項待人工確認。」
- 有 SKIP → 在結論中加註「（N 項因範圍限制略過）」

### 5. 驗收明細

每條驗收條件產出一個段落。

| 欄位 | 資料來源 | 說明 |

**實際結果**：系統成功回傳 15 筆資料，包含推播標題、發送數、開封數等欄位，格式正確

## 操作敘述翻譯規則

AI 在執行每個驗證步驟時，**同步**產生對應的人話敘述。以下為翻譯對照表：

### Playwright MCP 操作對照

| Playwright 操作 | 人話敘述模板 | 範例 |
|----------------|------------|------|
| `browser_navigate({ url })` | 開啟頁面「{頁面名稱}」 | 開啟推播統計查詢頁面 |
| `browser_click({ element })` | 點擊「{元素描述}」按鈕/連結 | 點擊「查詢」按鈕 |
| `browser_type({ element, text })` | 在「{欄位名稱}」欄位輸入 {值} | 在「開始日期」欄位輸入 2026-01-01 |
| `browser_fill_form({ fields })` | 依序填入表單：{欄位1}={值1}、{欄位2}={值2} | 依序填入表單：開始日期=2026-01-01、結束日期=2026-03-18 |
| `browser_select_option({ element, value })` | 在「{欄位名稱}」下拉選單選擇「{選項}」 | 在「排序方式」下拉選單選擇「日期降冪」 |
| `browser_snapshot()` | 觀察頁面內容 | 觀察查詢結果表格 |
| `browser_take_screenshot()` | 截取畫面存證 | 截取查詢結果畫面存證 |
| `browser_wait_for({ text })` | 等待頁面顯示「{文字}」 | 等待頁面顯示「查詢完成」 |
| `browser_press_key({ key })` | 按下 {按鍵} 鍵 | 按下 Enter 鍵 |
| `browser_hover({ element })` | 將滑鼠移至「{元素描述}」上方 | 將滑鼠移至圖表區域上方 |

### chrome-devtools-mcp 操作對照（--deep 模式）

| chrome-devtools 操作 | 人話敘述模板 |
|---------------------|------------|
| `click({ selector })` | 點擊「{元素描述}」 |
| `type_text({ text })` | 輸入「{文字}」 |
| `take_snapshot()` | 觀察頁面內容 |
| `take_screenshot()` | 截取畫面存證 |
| `wait_for({ text })` | 等待頁面顯示「{文字}」 |
| `evaluate_script({ expression })` | （不納入操作敘述，屬技術驗證） |
| `list_console_messages()` | （不納入操作敘述，屬技術診斷） |
| `list_network_requests()` | （不納入操作敘述，屬技術診斷） |

### API 操作對照

| API 操作 | 人話敘述模板 | 範例 |
|---------|------------|------|
| `curl GET /api/xxx?params` | 透過系統 API 查詢{功能描述}（參數：{參數說明}） | 透過系統 API 查詢推播統計（日期範圍：2026-01-01 至 2026-03-18） |
| `curl POST /api/xxx` | 透過系統 API 新增{功能描述} | 透過系統 API 新增推播標籤 |
| `curl PUT /api/xxx` | 透過系統 API 更新{功能描述} | 透過系統 API 更新推播內容 |
| `curl DELETE /api/xxx` | 透過系統 API 刪除{功能描述} | 透過系統 API 刪除指定標籤 |
| HTTP 狀態碼回傳 | 系統回應{狀態描述} | 系統成功回應，回傳 15 筆資料 |

### 翻譯原則

1. **不出現程式碼**：不寫 selector、URL path、HTTP method 等技術細節
2. **使用使用者可見的文字**：按鈕名稱用頁面上的實際文字（如「查詢」不是 `#queryBtn`）
3. **合併連續操作**：`click` → `wait_for` → `snapshot` 合併為「點擊 XX 按鈕，等待頁面載入完成」
4. **結果用白話**：「HTTP 200, 15 rows」→「系統成功回傳 15 筆資料」
5. **省略技術診斷**：`evaluate_script`、`list_console_messages`、`list_network_requests` 等技術操作不納入操作敘述

## 錯誤處理策略

### `/minimax-docx` Skill 不可用

```
觸發條件：步驟 10.4 嘗試呼叫 /minimax-docx 時 Skill 不存在
處理方式：
  1. 顯示警告：「⚠️ 找不到 /minimax-docx Skill，無法產出 Word 報告。」
  2. 提示安裝：「請確認 minimax-skills plugin 已安裝。」
  3. 提示替代：「verify.md 已包含完整驗證結果，可手動整理為報告。」
  4. 不阻斷流程 → 驗證結果（verify.md）已完整產出
```

### 截圖嵌入失敗

```
觸發條件：Markdown 中引用的截圖路徑不存在或檔案損壞
處理方式：
  1. 在報告對應位置標註「（截圖不可用：{檔名}）」
  2. 繼續產出報告其餘部分
  3. 在完成提示中加註：「⚠️ {N} 張截圖嵌入失敗」
```

### report-config.md 讀寫失敗

```
觸發條件：~/.claude-company/feature-workflow/ 目錄不存在或權限不足
處理方式：
  1. 嘗試建立目錄
  2. 若失敗 → 本次所有欄位直接詢問使用者，不存檔
  3. 在完成提示中加註：「⚠️ 報告設定未能儲存，下次仍需重新輸入」
```

### verify.md 無 human_steps 註解（向下相容）

```
觸發條件：使用者對舊版產出的 verify.md 執行步驟 10
處理方式：
  1. 偵測到無 human_steps 註解 → 進入降級模式
  2. AI 從 verify.md 的技術驗證內容反推操作敘述
  3. 在報告封面加註：「※ 操作步驟由系統自動轉譯，可能與實際操作有微差異」
  4. 降級模式下的翻譯品質預期較低，但仍可產出可讀的報告
```

### 使用者中途取消

```
觸發條件：步驟 10.1 或 10.2 詢問過程中使用者輸入 n 或中斷
處理方式：
  1. 顯示：「已取消報告產出。verify.md 已保留作為技術紀錄。」
  2. 不產出任何 .docx 檔案
  3. 不建立 report-config.md（若尚未存在）
```
