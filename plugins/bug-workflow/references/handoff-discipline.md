# Handoff 斷點保險（共用紀律）

> **目的**：讓 CREW 長任務在**任何時點中斷**（crash、關機、隔天重開）時，
> 新 session 都能靠 `.spec/{slug}/handoff.md` 精確接手，**最多損失一個工作單元**。
> 本紀律不對抗 auto-compact、也不主動中斷 session —— 它只保證中斷發生時，交接檔已經在磁碟上。

---

## 觸發紀律：進度即寫

- skill 開始執行時，`.spec/{slug}/handoff.md` **不存在就先建立**（用下方模板，先填目標與階段）。
- **每完成一個工作單元，立即更新 handoff.md**：刷新「最後更新」時間戳與 N/M 進度，
  把該單元從「進行中 / 未完成」移到「已完成（附證據）」並附上證據。
- 禁止「等做完一批再一次補寫」—— 中斷不挑時間，事後補寫等於沒有保險。

---

## 各 skill 的工作單元

### plan-build

一個工作單元 = **一個檔案**。由 Agent Teams **leader 在 worker 回報後寫入** handoff.md；
worker 不碰此檔（避免多成員同寫衝突）。

### plan-review

一個工作單元 = **一位審查員的報告**。

### plan-security

一個工作單元 = **一個掃描層**（Layer 1 靜態規則 / Layer 2 上下文感知 / Layer 3 對抗性思維）。

### plan-verify

一個工作單元 = **一條驗收條件**。

### bug-investigate

一個工作單元 = **一個假說的驗證結果**（確認或否定都算完成一個單元）。

### bug-fix

一個工作單元 = **一個修復步驟** —— 根因確認、程式碼修改、迴歸測試各算一個單元。

---

## bug 型任務無 `.spec/{slug}/` 目錄時

bug 流程（`/bug-start` 建立的任務）預設不建 `.spec/` 目錄。此時**建輕量目錄，只放 handoff.md**，
不建其他 .spec 檔案。slug 取法：

1. bug 流程以 Notion「修復分支」欄位對應當前 Git branch 識別任務（見 bug-workflow plugin 的 `references/locate-bug.md`），
   沒有獨立的 slug 慣例 → slug 用**當前 Git branch 名去掉分支前綴**（`feature/`、`fix/`、`hotfix/`）。
   例：branch `fix/push-timeout` → `.spec/push-timeout/handoff.md`。
2. 若 bug 任務由 `/plan-start` 建立（`.spec/{slug}/` 已存在）→ 直接沿用該目錄與 slug。

## handoff.md 模板

```markdown
# Handoff — {slug}

> 目標：{一句話說明這個任務在做什麼}
> 接手：新 session 輸入 `/plan-next {slug}`
> 最後更新：{ISO 8601 時間}｜階段：{skill 名}（{N/M} {單元}）

## ⚠ 歧義點與風險（接手先讀）

## 已完成（附證據）

## 進行中 / 未完成

## 接手前要準備

## 本階段決策紀錄
```

各段落填法：

| 段落 | 填什麼 |
|------|--------|
| 頁首引言 | 目標（一句話）、接手指令、最後更新時間；「階段」= 當前 skill 與單元進度（如 `plan-build（3/7 檔案）`） |
| ⚠ 歧義點與風險 | 規格沒寫清楚之處、用保守解讀猜的決定、可能踩雷點 |
| 已完成（附證據） | 每項一行：做了什麼＋本 session 證據（測試輸出摘要、檔案路徑、指令結果） |
| 進行中 / 未完成 | 剩餘工作單元清單；做到一半的單元標注確切中斷點 |
| 接手前要準備 | 環境需求（branch、服務啟動、環境變數）、接手前要先讀的檔案 |
| 本階段決策紀錄 | 本 skill 執行期間的取捨與理由，一行一條 |

---

## 硬規則

1. 「已完成」每項**必附本 session 的證據**（測試輸出、檔案存在、指令結果）；
   沒有證據的項目只能列在「進行中 / 未完成」，不得寫進「已完成」。
2. **歧義點置頂**：一律寫在「⚠ 歧義點與風險（接手先讀）」段，不得埋在結尾或散落他段。

---

## 生命週期

| 階段 | 動作 |
|------|------|
| skill 開始執行 | handoff.md 不存在 → 先建立 |
| 每完成一個工作單元 | 立即更新（進度即寫） |
| `/plan-close`、`/bug-close` 結案 | **刪除** handoff.md（bug 型輕量目錄若因此變空，連同目錄一併刪除） |

handoff.md 是**純本地**的過程性檔案：**不同步 Notion**、不進知識庫、結案即刪。
