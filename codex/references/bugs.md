# Bug 調查與修復

按觀察 → 重現 → 假說 → 驗證 → 根因的順序縮小問題。
從可觀察行為開始：觸發輸入、預期/實際結果、版本/環境、影響範圍。
每個假說寫可證偽的預測，選最小實驗；保存支持/反駁證據，不把相關性當原因。
三次同類失敗後改查前提、環境或交互作用，必要時提出會改變調查方向的問題。

調查預設讀取程式、測試與已授權的資料；DB 的讀寫範圍依實際授權。
根因需連到程式檔案與符號，修復能說明為何會消除原觸發情境。
修復先重現舊行為，再改必要部分，再驗證原案例與受影響邊界。
測試應捕捉可觀察錯誤；不要為微小文案或格式改動製造無意義測試。
不因修 Bug 順便重構無關模組；新的風險用決策/取捨記錄。

工作進度用 state unit 保存測過的假說、證據與剩餘疑點。
Bug 結案摘要包含症狀、根因、修復、迴歸證據、適用環境與仍待部署事項。
