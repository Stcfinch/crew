# 驗證、審查與報告

驗證以 plan.md 驗收條件為準；逐項對應輸入、操作、預期、實際、證據。
PASS 代表實際執行且符合條件；FAIL 代表有反例；WARN 包含未驗證、環境限制或接受的已知風險。
不要把工具 unavailable、測試 skipped 或只有靜態閱讀寫成實際驗收通過。
修復後只重跑足以涵蓋變更的範圍，依 repo 必要 gate 補驗。

瀏覽器使用 host 可用工具，遵循其登入/操作/截圖規則；
不要為了跑上游 CDP 範例繞過 host 的瀏覽器限制或暴露 debug port。
使用者要求 E2E 時優先既有 test runner，指出需人為操作的部分。

審查按三個角度：
- 邏輯：輸入與狀態轉移、錯誤路徑、邊界與相容性。
- 品質：和現有慣例是否一致，新增抽象是否有實際需要。
- 效能：查詢/迴圈/資源生命週期的具體成本，不憑空猜瓶頸。
發現需要檔案位置、觸發情境、影響與修法；沒有發現直接說明檢查範圍與限制。

報告暫存於 .spec/<slug>/.cache/。Word/Excel 依當前對應技能產出與驗證，
沒安裝時交付 Markdown 並標記未完成格式。原上游的品牌樣式與特定 runner 不自動安裝。
plan.md 只記摘要和產物位置；狀態透過 state result + state set 更新。
