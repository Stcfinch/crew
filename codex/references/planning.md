# 規劃與文件契約

plan.md 只寫從程式碼看不到的目標、理由、取捨、驗收與證據摘要。
六個二級標題固定為：
1. 目標與範圍
2. 驗收條件
3. 決策紀錄
4. 已知取捨與風險
5. 指路
6. 檢查報告摘要

spec pass：定義觸發條件、可觀察結果、錯誤情境與不做的範圍，避免抽象「正常運作」。
db pass：辨識 schema、資料回填、相容性、鎖定/效能與回滾風險；
有 SQL 寫在 deploy.sql 的編號 Step，不在 plan.md 抄 DDL。
arch pass：閱讀現有實作後記錄選擇原因和整合界線，用程式錨點指向事實。
沒有程式碼時不要造不存在的 @code 錨點；允許明確標成待實作，D7 WARN 要如實報告。

錨點：@code:src/auth.ts#authenticate；SQL：@sql:deploy.sql#users。
行號提示寫在錨點外，例如 (L42)，不作為穩定識別碼。
只有實際查核後才能寫入 frontmatter verified_at_commit；初始空白是刻意的。

每次局部修改前重新讀最新版本，保留其他 pass/使用者新增的決策。
修改 schema、方法簽章或類別後更新程式；文件記錄「為什麼」，避免另一份程式碼抄本。
